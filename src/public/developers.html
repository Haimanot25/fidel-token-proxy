Build with Fidel Token Proxy

An OpenAI-compatible, provider-agnostic gateway that normalizes Ethiopic scripts (Amharic, Afaan Oromoo, Tigrinya) to cut LLM token bloat, latency, and cost. Drop-in base URL for OpenAI, Anthropic, Gemini, Groq, and more.

Why app developers use Fidel

💸

Fewer tokens per Ethiopic request via homophone canonicalization and dedup.
⚡

Swap OpenAI ↔ Anthropic ↔ Gemini ↔ Groq with one header or path change.

Quick start

git clone https://github.com/your-org/fidel-token-proxy
cd fidel-token-proxy
cp .env.example .env   # add your API keys
npm install
npm start
# → http://localhost:8080  (base URL: http://localhost:8080/v1)

Point any OpenAI-compatible client at http://localhost:8080/v1. Fidel normalizes requests and forwards to your configured upstream provider.

Authentication

Pass your provider API key via Authorization: Bearer <key>, or store it once in Fidel (Settings) and omit the header. 

curl http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"ሰላም"}]}'

Providers

Fidel is provider-agnostic. Supported providers:

OpenAI
Anthropic
Gemini
Groq
Together
Mistral
DeepSeek
Ollama
OpenRouter
Cohere

Select a provider per request via path, header, or query param.

# Path
curl http://localhost:8080/v1/providers/anthropic/chat/completions ...

# Header
curl -H "X-Provider: gemini" http://localhost:8080/v1/chat/completions ...

# Query
curl "http://localhost:8080/v1/chat/completions?provider=groq" ...

Normalization

Ge'ez homophones are canonicalized and zero-width artifacts stripped before tokenization. 

curl -X POST http://localhost:8080/api/normalize \
  -H "Content-Type: application/json" \
  -d '{"text":"ሐኀ ሠላም ፀሐይ ዐማርኛ"}'
# {"normalizedText":"ሀሀ ሰላም ጸሀይ አማርኛ","savingsPercentage":...}

Semantic caching

Recurring system prompts are hashed (SHA-256) and stored in SQLite. Repeat requests with the same system prompt increment the cache hit counter, reducing redundant token re-transmission.

Settings API

curl -X POST http://localhost:8080/api/providers/groq/settings \
  -H "Content-Type: application/json" \
  -d '{"apiKey":"gsk_...","defaultModel":"openai/gpt-oss-20b"}'

Settings are persisted in SQLite and override environment variables at runtime.

Models API

curl "http://localhost:8080/api/providers/groq/models?refresh=1"

Returns active models from the upstream provider. Results are cached for 1 hour; pass refresh=1 to force re-fetch.

Stats API

curl http://localhost:8080/api/stats
# {"total_requests":...,"total_raw_tokens":...,"tokens_saved":...,"cache_hits":...}

SDK snippets

JavaScript (OpenAI SDK)

import OpenAI from 'openai';
const client = new OpenAI({ baseURL: 'http://localhost:8080/v1', apiKey: process.env.OPENAI_API_KEY });
const res = await client.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'ሰላም' }]
});

Python

from openai import OpenAI
client = OpenAI(base_url="http://localhost:8080/v1", api_key="sk-...")
r = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "ሰላም"}]
)

Errors & limits

Errors are returned in OpenAI-compatible format: {"error":{"message":...,"type":...}}. Upstream status codes are passed through. Streaming responses use SSE (text/event-stream).
